# Lensmap 0.4.0

**Release candidate; publication and registry-only acceptance are pending.**
The four-package cohort targets npm's `latest` channel. The authoring format
remains experimental and document `version: v1` is unchanged.

## Packages and pinning

Release these packages together at the same exact version:

- `@lensmap/document@0.4.0`
- `@lensmap/language-server@0.4.0`
- `@lensmap/astro-loader@0.4.0`
- `@lensmap/starlight@0.4.0`

After publication, existing Astro/Starlight consumers can pin the packages they
use explicitly, rather than depending on a floating range:

```sh
pnpm add --save-exact @lensmap/starlight@0.4.0 \
  @lensmap/astro-loader@0.4.0 @lensmap/document@0.4.0
```

Keep the host's required framework/peer integrations configured. This is not a
migration of another codebase or a claim that its build has been qualified.

For the language-server runtime:

```sh
npm install --global @lensmap/language-server@0.4.0
lensmap-lsp --configure-zed
```

Inspect and merge generated settings into the intended workspace, then restart
the server and open a fresh preview. This npm release does not update the
separately pinned Zed extension or qualify its managed-runtime download.

## Added

### Default node styling

- Quoted `"*"` rules in `node_styles` automatically supply defaults to every node,
  including shorthand strings, nested/placeholder thoughts and portals.
- Named classes and inline styles override normal defaults regardless of the
  default rule's dictionary position. `!important` retains priority across all
  three origins. Explicitly listing `"*"` does not apply it twice.
- Defaults support the same declaration forms and conditional rules as classes.

### Responsive styling and positioning

- CSS style strings accept nested `@media` and unnamed size `@container` blocks.
  Media queries use browser conditions; container queries use the individual
  map canvas, including a narrow map embedded in a wide page.
- `--lensmap-x` and `--lensmap-y` specify finite signed world coordinates before
  camera/lens projection. Axes are independent; explicit `auto` releases a pin,
  while omission retains the corresponding legacy `position` fallback.
- Conditional programs survive LSP and Astro/Starlight transport. Exported
  `NodeStyleCondition` metadata and `resolveNodePresentation` support resolving
  validated programs without requiring a browser in the document engine.
- Responsive changes preserve camera and selection. Panning and zooming do not
  change condition matching or initiate automatic world-layout recomputation.

See [node styling](../node-styling.md) and
[responsive presentation](../responsive-node-styling.md).

## Fixed

- Styling diagnostics select the offending declarations/properties through YAML
  mappings, quoted/folded strings and supported aliases instead of highlighting
  an unrelated field or the whole style block.
- Invalid inactive conditional branches still produce diagnostics and retain
  the last valid presentation until corrected.
- Auto-sized circles refresh their intrinsic measurement when viewport-relative
  typography changes within a still-matching branch, even at a fixed canvas size.
- Standalone map navigation no longer requires secure-context-only
  `crypto.randomUUID()`; visit/attachment identities also work on HTTP hosts.
- Installed-runtime browser qualification uses the package's own bundled viewer,
  and Starlight artifact tests wait for their own build before reading outputs.

## Website and documentation

The repository also gained the interactive homepage, searchable documentation,
source-backed live examples and navigable example maps. Spatial-focus and mobile
hero compositions were refined; responsive hero coordinates now live in the
map's authored CSS rather than a TypeScript position table. The website is a
separate deployment, not another npm package in this cohort.

## Compatibility and exclusions

Existing maps retain default circles/radial layout and existing source/navigation
behavior when they do not use the new styling features. `"*"` is now reserved as
an automatic default rule. CSS coordinates take precedence per axis over legacy
positions. Related npm packages should use matching cohort versions.

SVG node shapes, custom shape definitions, new text-fit controls, directional or
mixed-layout APIs and layout-option project configuration are still design work;
they are not implemented by 0.4.0. Project JSON configuration still selects the
connection vocabulary through `types`. No new resource loading, executable map
content, animation or arbitrary stylesheet injection is authorized.

Host font metrics and conservative circle fitting remain relevant. Fresh native
Zed managed-download, Firefox/WebKit, physical-touch and large-graph performance
acceptance are not claimed. Versioned artifacts and post-publication registry
consumption are recorded separately in [npm release evidence](../npm-release.md).
