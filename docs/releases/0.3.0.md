# Lensmap 0.3.0

Lensmap 0.3.0 adds author-defined connection vocabularies and CSS-based node
presentation across the document engine, browser viewer, language-server bridge
and Astro/Starlight integrations. The authoring format remains experimental;
`version: v1` is unchanged.

## Packages and channel

The release cohort is:

- `@lensmap/document@0.3.0`
- `@lensmap/language-server@0.3.0`
- `@lensmap/astro-loader@0.3.0`
- `@lensmap/starlight@0.3.0`

All four target npm's **latest** tag. Keep related packages on the same cohort
version. Publication uses the qualified pnpm tarballs, whose internal workspace
references are rewritten to exact 0.3.0 dependencies; source manifests retain
`workspace:*`.

## Custom connection vocabularies

- Declare named relationships in document-local `connection_types`, or share a
  YAML `.lenstypes` vocabulary selected by project-root `lensmap.config.json`.
- Inherit from custom or built-in types, restyle existing names and override only
  explicitly supplied fields. Effective precedence is built-ins, shared file,
  then document-local declarations.
- Configure connector colour, SVG stroke width, line preset, endpoint markers
  and paired forward/reverse wording without assigning executable domain logic.
- Project-aware language tooling supplies vocabulary diagnostics, completion,
  hover and definitions. Live reload retains the visibly stale last valid map
  when configured data becomes invalid, and recovers when corrected.
- Ordinary untyped connections remain valid without configuration. Styling does
  not grant file/network authority or change portal capability.

See [the declaration reference](../custom-connection-types.md) and
[the shared-vocabulary example](../../examples/custom-connection-types/README.md).

## Node styling and measured sizing

- Rich nodes accept `classes` and inline `style`, with reusable rules in
  document-local `node_styles`.
- CSS declaration strings and ordered YAML mappings share validation. Class
  declaration order, inline specificity, shorthand order and `!important`
  priority are preserved.
- The initial supported profile includes colours, host-available fonts, borders,
  padding, decorative icons and circle sizing. It does not load external CSS,
  fonts or executable animation code.
- `--lensmap-scale` accepts a positive numeric factor or `auto`. Auto-sized
  circles grow around the actual rendered summary, padding, border and icons;
  text is not shrunk to fit a fixed bubble.
- Resolved circle radii feed automatic layout, lens clearance, Overview fitting,
  neighbourhood rings, loops, both connector ends and continuation stubs.
  Authored pins stay exact; paint-only updates preserve exploration state.
- Measurement excludes temporary selection borders and retains hidden circles'
  sizes across neighbourhood refreshes, remeasuring content when remounted.
- Source edits preserve the authored Markdown and style form. Invalid styling
  reports diagnostics and retains the last valid presentation.

See [the styling reference](../node-styling.md) and
[the self-contained example](../../examples/node-styling/README.md).

## Upgrade and qualification

For the standalone language-server runtime:

```sh
npm install --global @lensmap/language-server@0.3.0
lensmap-lsp --configure-zed
```

Inspect and merge generated settings into the intended workspace; the command
prints settings rather than modifying the editor. This npm cohort does not
release a new Zed extension or change its separately pinned managed runtime.
Existing explicit binary overrides can select the newly installed runtime.

The feature source passed workspace tests/typechecks/lint/builds, 43 Chromium
browser regressions, isolated four-package production installation, native
Astro/Starlight checks and independent review. The versioned release artifacts
are qualified separately before publication; registry availability and a fresh
registry-only consumer are verified afterward. Publication status and retained
release evidence are recorded in [npm releases](../npm-release.md).

Known limits remain: host-available font metrics, conservative circle fitting
and mixed-radius layout spacing, no new native Zed managed-download acceptance,
no fresh Firefox/WebKit or physical-touch qualification, and no large-graph
performance claim. Animation, external style discovery and future renderer
features are not part of 0.3.0.
