# Lensmap: first web-app slice

## Approved direction

See `../HANDOFF.md` for canonical product decisions and schema exploration. Lensmap is text-first exploratory mapping with cycles/convergence, not a shape-drawing app or a world-article navigation graph. TypeScript + pnpm + Turborepo; web app first, reusable embedded viewer second, language server third.

## Current implementation boundary

React + Vite in `apps/web`, with a pure spatial projection module, an editable YAML playground, and an explicitly versioned Zod schema. **`version: v1` is incomplete and experimental**, not a frozen compatibility contract. See `schema-v1.md` for the current subset and validation boundary. There are no placeholder viewer/LSP packages. Markdown notes and collapsed titles are rendered with react-markdown (raw HTML is not enabled); prose fragments resolve authored node IDs, not renderer keys. Heading slug generation and section ownership remain future work.

The camera translates/scales a stable world layout. The lens uses **one nonlinear spatial falloff for placement and desired circle size**, normalized to the viewport ellipse. There is no separate logarithmic distance warp or derivative-based circle-size curve. Lens-only base spacing and circle size keep nearby ideas prominent; this is spatial, not child-count or graph-distance sizing. A view-only clearance pass can reduce crowded circle sizes without moving their centres. Below normal strength the view continuously blends back to uniform projection; strength zero and Overview leave the underlying layout undistorted. Edges follow the actual limited circle extents, with visible loops for self-links. Selection is separate from spatial prominence; activating a node explicitly centres it. The overview fits undistorted positions and is navigated by selecting nodes, not by pretending tiny nodes constitute a fully expanded content view. Branches have stable contrasting colours and halos; cross-links additionally use dashes and arrowheads.

Controls: pointer drag (including single-pointer touch), wheel zoom, zoom buttons, lens strength, reset, lens/overview switch, native keyboard-focusable node buttons and the keyboard-navigation trial below. There are no animated camera flights. Deliberate neighbourhood navigation has a 160 ms whole-scene opacity reveal, disabled for reduced motion; edges and their endpoints are never animated separately.

Selection adds static branch-coloured outline glows to the active node and one-hop endpoints of incident explicit edges, including incoming/outgoing cross-links and loops. Only incident connectors glow; an edge between two neighbours does not become incident by association. Prose-only targets and transitive descendants remain ordinary context. The selected circle has a slightly brighter fill/border/glow rather than an extra solid outline; a visible outer ring remains for keyboard focus. Modestly thicker borders/strokes provide a non-colour cue, while keyboard outlines, cross-link dashes/arrowheads and branch colours retain their separate meanings. Incident SVG groups paint last so unrelated dark edge halos cannot cover them. This presentation does not change topology, authored layout, spatial prominence, clearance or the shared uniform zoom, and remains visible in Overview without selecting neighbours or adding motion.

Pointer gestures may start on either the map or a node, but not on zoom controls. Pointer capture stays on the original node button/background; events bubble to the map even when the pointer crosses a node. Four units of movement distinguishes drag from click. A real drag suppresses its resulting pointer click without suppressing keyboard activation. Pointer-up/cancel/lost-capture clears drag state; ordinary clicks remain native button activation.

Manual zoom is a uniform transform **after** lens deformation, centred on the viewport. It scales all node circles, text, positions, edge curves, strokes and arrowheads by the same factor; it must not feed back into the nonlinear lens-distance calculation. The renderer applies one shared DOM/SVG scene transform, while controls, focus guides and the sidebar remain fixed. Panning still changes spatial focus, and lens strength still changes focus/context distortion. Zooming in may deliberately take peripheral content outside the viewport; the compaction guarantee is not a hidden auto-fit that cancels manual zoom. Overview uses its fit scale through the same scene transform, with the inner SVG left unclipped so only the outer map viewport clips the final result.

`clearance.ts` works on unit-zoom projected circles. Each conflicting pair allocates the available radius with continuous squared nominal-radius weights, favouring the more central circle and never enlarging a nominal radius. Intersecting pairwise caps keeps the result independent of traversal order; there is no live force repacking while navigating. The target gap is six scene units. Context dots retain a two-unit radius unless already smaller; coincident/too-close fixed centres therefore cannot guarantee separation. The correction blends with lens strength below one and is bypassed in Overview. The pairwise implementation has quadratic cost; this small-graph experiment does not qualify large-graph performance or universally readable labels.

The sidebar has independent native disclosure sections for Selected thought, Explicit connections, and YAML playground. The first two start open; opening source does not replace them. The desktop divider resizes by pointer or keyboard (Left/Right, Home/End) while retaining map room; mobile stacks the sidebar beneath the map. The textarea can also be resized vertically. Drafts and disclosure states survive node/view changes; reload persistence is not implemented.

## Temporary neighbourhood navigation

Ordinary selection retains the stable full map and immediate-neighbour glow. Double-click or the Explore neighbourhood action deliberately enters a temporary one-hop radial arrangement. Clicking a neighbour explores its neighbourhood; double-click or Return to map surfaces in the normal lens at the current thought's canonical world position. Enter accepts the keyboard target and switches views; Shift+Enter is a compatibility alias. Escape is now viewer-focus-scoped and instead restores the pre-entry map camera/view, without accepting the target; the latest committed thought's notes may remain selected away from that restored centre. No extra view-selector tab or authored node/schema field is introduced.

`neighbourhood.ts` deduplicates bidirectional endpoint adjacency while retaining actual edge objects, loops and parallel edges. It copies visible node coordinates into a view-only radial ring, preserving cyclic source bearings and expanding by chord clearance for higher degree rather than dropping nodes. Complete neighbour-to-neighbour edges remain quieter context; only true boundary edges become fanned continuation segments. `NeighbourhoodContinuations.tsx` uses original target-branch colours and the same branch/cross CSS dash pattern as complete paths. Gradients only lower opacity toward the cut-off; incoming cross-link arrowheads remain at visible destinations, outgoing hidden destinations have none. No distant node/label or prose-derived edge is rendered.

Temporary positions feed the existing spatial lens/clearance and shared uniform scene zoom. Neighbourhood camera and lens-strength state are separate: entry starts from the normal strength, while local tuning does not overwrite the retained normal setting. Pan/zoom does not recompute the radial model, and returning restores the full map's original geometry and normal zoom/strength at the selected thought. Source Apply exits the temporary arrangement and cancels pending input; invalid drafts retain it. Sidebar text/drafts and canonical graph totals remain independent of the visible subset. Reset and Overview remain full-map operations.

Pointer single-click movement is deferred 350 ms to resolve a possible double-click without moving its target away first. Native keyboard activation and explicit/sidebar actions stay immediate. Pending activation and its double-click candidate are cancelled by dragging, view/control/source intent and unmount; a drag is not a dive. This initial window is not qualification of every system double-click preference or physical touch comfort. Narrow screens can still have compact labels; full notes remain in the sidebar and manual zoom remains available.

## Keyboard navigation trial

`navigation.ts` separates screen-centre targeting, fuzzy spatial candidate scoring, explicit-edge traversal and capped acceleration math. Displayed node centres are relative to the fixed viewport centre after the shared zoom; only visible centres can be spatial targets. Circle radii, graph distance and authored nesting do not determine orbital tiers. A 130 px central targeting region rejects empty-centre acceptance. Ctrl candidates lie within a 60-degree directional cone; distance/alignment and a bounded radial/tangential penalty choose between them with deterministic key ties, without wrapping or panning.

Camera, pending keyboard target and committed selection remain distinct. Plain panning resets the target to the central candidate. Ctrl+arrows move only the target, retained on modifier release. Space/Ctrl+Space commits and recentres within the current view. Shift+arrows start from that visible target, deduplicate real incoming/outgoing explicit neighbours and ignore loops/prose; the trial junction rule prefers directional alignment, then proximity and key. Visible geometry supplies directions; hidden neighbours use their source displacement relative to the origin, remaining eligible beyond the current neighbourhood. A successful local traversal derives the destination's radial neighbourhood; full-map traversal never enters it implicitly.

`useMapKeyboard.ts` installs viewer-scoped native listeners with current React Effect Events and one requestAnimationFrame loop, not OS repeat-driven panning. An 8 px tap nudge leads into time-integrated acceleration from 120 px/s at 900 px/s² to the configurable maximum (initially 900; toolbar range 120–1800 px/s). These are camera pan inputs before lens deformation, not a guarantee of identical apparent velocity for every warped circle. Direction changes reset acceleration; diagonals normalize. Release, viewer/window blur, backgrounding, modifiers, pointer/control intent, view/source replacement and unmount stop immediately. Large frame gaps are capped at 50 ms rather than causing a background-time jump.

Shortcuts apply only to the map background or node buttons, not toolbar/zoom controls, editor inputs or sidebar links. Alt/Meta/IME combinations and Tab remain native. A dashed pale target cue, visible target label and accessible announcement stay distinct from committed connection glow and native keyboard focus. The latest Escape contract replaces the earlier document-wide shortcut. Overview remains fit-to-map: plain pan is disabled, while browsing/acceptance work; Escape can restore Overview after a dive. Scoring, acceleration and maximum speed are trial/session settings; no schema, persistence or physical motion-comfort promise is introduced.

Before committing or entering a neighbourhood that would omit the viewer's currently focused node, focus transfers to the map background with scrolling prevented. Surviving node focus is retained; external/editor/control focus is not stolen. This keeps Shift traversal, Space acceptance and Enter switches usable across multiple neighbourhoods rather than leaving focus on the document body after React removes a button.

Ctrl+= / Ctrl++ / Ctrl+- are delivered through the same viewer/node focus gate. Only those matching shortcuts call preventDefault, leaving browser zoom available outside the viewer and preserving Alt/Meta/IME handling. Keyboard and button zoom share `zoomView` and the existing `zoomCamera` step/limits; they cancel queued activation and held panning without changing selection or lens strength. Neighbourhood zoom stays local. Overview consumes the focused shortcut but retains its fit, consistent with disabled zoom buttons. This qualifies browser-delivered Chromium events, not every platform-reserved shortcut or keyboard layout.

## Authored layout and source lifecycle

Apply parses YAML, validates Zod structure and references, normalizes shorthand, and computes missing positions before replacing the graph. Authored branch edges define a radial forest: each root's children circle it clockwise in source order, then descendants fan outward around their immediate parent. Maintained D3 collision relaxation runs once around those deterministic targets, fixing explicit positions and component roots. Cross-links/cycles remain visible edges but do not change hierarchy or attract nodes. The prior Dagre dependency has been retired. Invalid source keeps its raw draft and the last valid graph. Load sample replaces only the draft, not the applied map. Reset view affects the current graph's camera/selection, not its source. Canonical layout runs on Apply, never on pan/zoom or sidebar disclosure. The actual sample lives in `apps/web/src/sample.yaml` and uses the same pipeline as user-authored source.

`document/subtree.ts` now plans automatic branches bottom-up. Maintained `d3-polygon` convex hulls compact the occupied node-centre contours; the existing clearance radius pads their angular silhouettes analytically. Sibling intervals are packed clockwise in source order by their actual footprint, not subtree node count or one large bounding circle. Thin chains therefore do not consume the angular room of broad forks. Root children may use the full circle; non-root fans widen into their forward half-plane before a local link distance increases. A sufficient local distance is refined to sub-unit precision only if the angular intervals still cannot fit. Automatic branches rotate coherently, rather than relaxing every descendant into a neighbour's region.

The existing initial D3 collision pass remains fine adjustment, especially for authored constraints and independent component roots. Explicit coordinates are never rotated or translated with an ideal contour: automatic descendants rebase at their actual pinned parent. A constrained branch may consequently diverge from its ideal silhouette. Component-root placement is unchanged; this is not a globally optimal packing guarantee for multiple roots, concave free-space use or conflicting pins. No layout computation or whole-branch motion runs during camera navigation.

The default sample omits all authored positions. The exact previous positioned version is saved at `apps/web/examples/night-ferry-positioned.yaml`; after removing position fields, the two parsed documents are identical. Its first position-free comparison used the earlier left-to-right layout; the subsequent radial default changed only automatic layout. Clearance was then added with that fixed-fan geometry held fixed. The next contour-packing experiment changes only initial layout, keeping the lens, clearance implementation and both source samples unchanged. Source hot reload does not deliberately overwrite an existing draft/applied graph; re-Apply a valid draft for new automatic positions, or Load sample and Apply to switch source.

## Deferred contracts

Durable persistence, import/export, manual positioning UI, embedding API, language server, full-content overview, and a heading-anchor/history contract remain deferred. The v1 Zod schema and basic YAML source textarea do not imply embedded Markdown editor tooling or live node-ID completion. Optional IDs, recursive shorthand, explicit empty placeholders, summary overrides and prose/topology separation from the handoff are implemented within the current experimental subset.

## Evidence and open judgement

Use focused unit tests for projection/fit/camera invariants, native TypeScript/Biome/Vite/Turbo checks for tooling, and a small Playwright suite for actual rendered controls and navigation. Synthetic drag/touch checks do not qualify physical comfort, arbitrary overlaps, large graphs or the user's judgement of lens distortion. Those remain explicit hands-on evaluation work.

Turbo configuration follows installed 2.11.10 docs: `docs/README.md`, `crafting-your-repository/{structuring-a-repository,configuring-tasks,running-tasks}.mdx`, and `guides/frameworks/vite.mdx`. Builds cache `dist/**`; dev is persistent and uncached; tests/typechecks have no file outputs. Biome checks root and app files directly; no invented configuration-test framework.
